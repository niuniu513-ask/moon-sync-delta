## 修复方案：真实扩展 moon_vcdiff

直接依赖 `yangxixi00/moon_vcdiff@0.1.0`，复用默认码表、整数编码、结构检查和解码器。新增签名驱动的 VCDIFF 编码路径，发送端只有签名与新版内容，无需接收完整旧文件。它拓展上游的使用条件，而不是取代通用编码器。

证据为 `moon.mod`、`vcdiff.mbt`、`vcdiff_wbtest.mbt`、`examples/demo` 及 `scripts/verify_vcdiff.py`。示例明确区分上游双文件编码与本项目签名编码，并让原版解码器消费本项目生成的标准补丁。独立 Python 测试在编码时临时移走旧文件，检查标准补丁语义、结果及传输总成本。

不声称这是上游维护贡献、已获上游认可或已经合并 PR。此为独立仓库中的生态扩展，新增价值是否达到赛方门槛仍待复审。

## 与 moonrestore 的边界

撤下“增量备份项目”的定位、场景和关键词。不实现快照清单、CAS、备份存储、目录恢复或备份 CLI，也未接入 moonrestore，不能把它写成依赖或合作项目。任意二进制更新流程仍可能被备份应用利用，功能交集并未凭措辞消失；复审依据应是实际 VCDIFF 扩展及可复用新增能力。
