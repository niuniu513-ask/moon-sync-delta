# 选题与工程范围

## 为什么选择这个方向

一般字节差量编码器需要同时拿到旧数据和新数据。远端备份和设备更新时，发送方可能只能拿到
接收方的块签名。这个库把“接收方签名 → 发送方滑动匹配 → 接收方重建”做成可复用 API。
因此实际输入是任意二进制数据，不依赖一个特殊业务格式，也不限于某一种行业。

它不是全球原创：rsync 已解决类似问题。本项目的目标是补充 MoonBit 的具体工程能力。
已有 MoonHashKit、MoonChunk、MoonRestore 和 VCDIFF 项目，与同步、备份或差量有功能交集。
本项目的独立价值需要通过发送方 API 不接收旧数据、强校验防碰撞和完整端到端结果来说明。

## 三条场景链路

| 场景 | 接收方已有的数据 | 发送方已有的数据 | 交付结果 |
|---|---|---|---|
| 备份上传 | 旧备份及其签名 | 新备份、收到的签名 | 校验后的新备份 |
| 资源分发 | 安装端旧资源 | 新资源、安装端签名 | 校验后的新资源文件 |
| 边缘快照更新 | 节点旧快照 | 新快照、节点签名 | 校验后的完整快照 |

“普适”指可被不同应用复用，不表示所有输入都能节省流量。已压缩/加密数据整体变化时收益可能很低。

## 当前验收范围

核心库、签名/差量传输格式、文件操作入口、四后端测试、独立 Python 验证、README 和 CI 已创建。
本版不实现网络服务、目录备份系统、认证、文件权限同步、流式大文件 API 或 rsync 命令兼容。
源数据及帧大小有明确限制；格式、完整性和范围错误须显式失败。
